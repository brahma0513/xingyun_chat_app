# App 消息列表与单聊

## 本次范围

### 2026-09-12 未读与切号隔离

- 会话列表点击只负责跳转，不再提前清未读。聊天页显示后，通过 App 服务确认前台、页面 ID、会话 ID 和本次登录 sessionID，再清除该会话；不在本地伪造总未读为 0。
- App onHide 立即撤销已读权限；页面 onHide/onUnload 撤销该页面权限，取消尚未发出的已读请求。已提交到 SDK 的请求无法撤回。
- 同一会话的连续已读请求合并；失败在下次显示、收到消息、恢复网络或未读存储初始化完成时可重试。未读监听独立于页面，前台恢复与网络恢复主动刷新。
- 每次登录/退出使用不同 sessionID，即使退出后登录同一账号，也禁用旧聊天路由、清空旧标题和头像数据并卸载输入组件；不删除云端或 SDK 保存的历史消息。
- 页面恢复先等待 App 返回最新状态，不拿隐藏前的 ready 状态直接显示旧消息。列表及业务发消息入口携带本次 sessionID，避免跳转期间切号。
- 自动测试包含 `tests/im-read-state.test.mjs`，覆盖后台/旧页面/旧登录拦截、请求合并、失败重试、其他会话未读保留及状态握手；与其余 IM 测试一同运行。

真机验收（两个以上账号，现有自定义基座重新运行即可）：

1. A 向 B 发消息；B 停在个人中心，消息入口未读增加。
2. B 有两条不同会话未读时，进入其中一条，只清除该会话，另一条保留。
3. B 停在聊天页切后台，A 再发消息；B 回到前台可更新；停留在其他页面时不可自动清该聊天的未读。
4. B 退出/切到 C，再返回旧聊天页应提示重新进入；即使重新登录 B，旧页也不能直接发送。新消息列表不得保留其他账号会话。
5. 断网再恢复，验证未读刷新；跳转失败时不可清未读。云端历史消息不得被删除。

## 登录实现

后台签名接口及业务认证不变；App 服务通过 `native-sdk.js` 适配原生 LoginState，复用原串行 session 控制器。
只有一套原生 IM 登录。UserSig 不放 Vuex、URL、storage，也不打印原生调用参数。
nvue 通过 `im:request-status` / `im:status` 获取脱敏状态，`im:retry` 显式重登。
原生桥接若一直不回调，保持登录队列阻塞，防止迟到的旧登录覆盖新账号；此时需重启 App。
原生登录状态变化/被踢的最终行为需要双设备真机验证。

## 语音消息（2026-09-12）

- 输入栏点击麦克风切换语音，按住录音、松开发送、上滑取消；支持 1–60 秒，最后 10 秒同样可以取消。首次授权期间松手不会在授权后自动录音，需要重新按住。
- 录音使用全局单一监听桥；旧录音停止回调确认前不启动新录音。来电打断、切后台、退出页面、登录代次变化及 touchcancel 均取消，不自动发送。
- 点击语音播放/停止；播放其他语音或开始录音会停止当前播放。后台、销毁及迟到的下载回调不会恢复播放。

- manifest 增加 Record、Android RECORD_AUDIO 和 iOS 麦克风用途说明。两端都要重新制作并选择新自定义基座。模块说明：https://uniapp.dcloud.net.cn/tutorial/app-modules 。
- 真机验收：双账号互发并播放；首次授权/拒绝授权；授权前松手；短录音；上滑取消及滑回；60 秒自动结束；录音时切后台、来电、返回；断网发送后恢复网络重试；失败文件被清理；切换账号后旧任务不发送。
- 自动测试覆盖录音状态机及播放生命周期；模拟测试和 App 资源编译不能代替真机麦克风及原生打包验收。

## 验收清单

### 同账号重连误关闭会话修复（2026-09-12）

- `accountSessionID` 只随业务登录/退出、用户或租户变化递增；同账号凭证刷新与 IM 显式重试不改变它。页面导航携带此值，防止跳转途中切号后打开旧路由。
- `sessionID` 仍随 SDK 重新登录递增，继续隔离原生组件、旧图片任务及旧已读请求，不可用 `accountSessionID` 替代这些异步校验。
- 聊天页以业务登录批次判断是否关闭会话，同账号重连后保留会话和标题；若服务端返回的实际 IM userID / SDKAppID 改变，仍关闭旧会话。
- 退出后即使马上登录同一账号，旧页面仍失效；被踢不会自动抢登，用户点击重试成功后可继续原会话。
- 本次仅改 JS/nvue，不涉及新的原生插件或基座配置。停止运行再运行到手机即可验证这项修复。
- 真机重点：反复切前后台、断网恢复、同账号连接重试不出现“登录状态已变化”；真正退出/切号仍提示返回列表。

### 双设备验收

聊天页连接文案延迟 500ms 显示：快速获得登录状态时不闪字；持续等待才显示“正在连接聊天服务…”。登录失败、未登录、被踢和账号变化提示不延迟。页面隐藏/卸载或连接恢复时清理计时器，重新进入重新计时。仅调整显示，不延迟聊天组件就绪。

消息列表跳转时不显示状态占位：页面隐藏、后台或等待 App 状态确认时，不将 `imReady=false` 当成重新连接。蓝色“点击重试 / 登录”仅在已确认的未登录、被踢或失败状态显示；连接中点击占位不会强制重登。

两台手机登录不同账号 A/B：

- A 从消息页输入 B 的数字 ID，发送文字；B 在前台收到。
- B 停在会话列表，A 发消息：摘要/时间/未读增加；B 进入聊天后未读清零。
- B 退出聊天页或切后台后，A 发消息：不可被隐藏页面自动标记已读。
- 返回会话、重启 App 后可加载历史；下拉加载更早历史。
- 断网发送出现失败状态，恢复网络后点击失败图标重试。
- 退出账号、切换账号不展示旧消息；同账号异地登录、显式重试需要真机确认。
- 检查安卓和 iOS 键盘弹出/收起、返回键、安全区，不遮挡最后一条消息。

自动测试：`node --test tests/im-session.test.mjs tests/im-native.test.mjs tests/im-vue2-build.test.cjs`。
测试使用模拟原生桥，不能代替 UTS 原生编译及真机消息验收。

## Vue2 TypeScript 编译修复（2026-09-10）

项目原先无 tsconfig，HBuilderX 默认扫描整包 TS，导致未引用的 LiveSeatState / RoomState 等 Vue3 文件报错。

`types/uni-components.d.ts` 声明由 HBuilderX 提供的 nvue/vue 组件与 UTS 原生模块边界。
两个兼容工具不再静态导入 Vue2.6 缺少的 ref/reactive/onMounted/onUnmounted。
本地 HBuilderX 5.24 + 自带 Node18 的 App 资源编译通过（`unpackage/im-build-check`）；产物不含 LiveSeatState/RoomParticipantState。
这仅代表 JS/nvue 资源编译通过，不代表 Android/iOS 云打包或真机登录已验收。仍须重新制作自定义基座。
